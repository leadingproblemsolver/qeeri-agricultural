# 05 — Forward deployment, research collaboration and external consequences

**Research purpose:** give a real human a bounded tool that helps make one decision while preserving evidence, review and a safe refusal. **Local integration exists; enterprise adoption does not.**

## Existing code and interfaces
- [Local stdio MCP interface](../../../research_mvp/mcp_server.py), [MVP reproducibility](../../../research_mvp/README.md), [source/decision receipts](../../../research_mvp/qeeri_brain.py).
- [Existing independent software proof in Reality Ontology Runtime](https://github.com/leadingproblemsolver/reality-ontology-runtime) — separate project; no QEERI integration demonstrated.
- [Source-linked context and handoff in Living Context Engine](https://github.com/leadingproblemsolver/living-context-engine) — separate project; no QEERI deployment demonstrated.
- [Mentor and form obligations](../../../docs/05_REVIEW_AND_CONTINUITY/README.md). Institutional participant or lab records are **private**, not portfolio demo data.

## Start condition: one authorized external problem
Have an actual QEERI mentor or agricultural operator specify: input documents/measurements they may share, decision they need, source rights, error/abstention rule, and who signs off. Begin with **manual input → evidence-linked checklist/report → human decision**, not a chatbot product.

**Minimum industry slice, after research review:** run a local CLI/MCP on permitted non-sensitive data to return (1) sourced claim or missing-input blocker, (2) explicit limits, (3) accountable reviewer request and (4) reproducible receipt. Test real acceptance with the recipient. No construction specs, external cloud uploads, autonomous controls or deployment without authorization.

## Communication proof — only real external receipts
- Research collaboration: question sent, exact reviewer response, revision accepted/rejected. Silence is not approval.
- Cross-group/cross-cultural work: verified joint artifact, scoped ownership and actual review; never infer from contacts or introductions.
- Professional portfolio: purpose → input → code/procedure → observed result → limitation → who reviewed and changed their behavior.
- Do **not** claim Microsoft collaboration, employment or enterprise forward deployment from a repository or application prompt.

**Exit receipt:** authorized handoff plus observer feedback and measured utility, or explicit blocked/declined status. **Industry signal:** boundary-aware local AI integration, not a production enterprise deployment.
